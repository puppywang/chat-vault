# Codex 查找预算与断点修复：0.12.1

## 问题

目标 ChatGPT conversation：`6abfcbcd-842c-83ec-a19a-c1f2ea21af8c`。
用户在 0.12.0 的深度查找中得到「已检查 9/9 个根线程、238 页 items、6 项读取失败、达到读取预算」。
目标页面探针确认后台和页面均为 0.12.0，因此不是没有重新加载旧版。

根因是查找调度和状态处理：

1. 240 次预算包含 2 次目录请求，剩下 238 次历史请求；耗尽预算被逐根捕获为读取错误，误显示多项失败。
2. 每次调用都创建新的目录和 item 游标。重复点击再次从最早一页开始，无法越过上次截断的位置。
3. `rootsChecked` 在开始处理线程时加一，并非该线程已经读完。9/9 不能代表完整历史扫描完成。
4. 深度扫描旧记录优先，长线程会占用大量时间；单次限额下没有跨批调度位置。
5. 当前快照 `current_node` 追加助手或工具消息时也会改变；此前把这种正常追加误当作切换分支。

## 实现

- 深度查找使用 `sortDirection: desc`，初始每页 100 条；普通查找仍保留开头优先的兼容路径和每页 20 条。
- 保留每根线程的游标、页大小、已读页数、分页环检测集合、完成状态和已验证候选。
- 目录列表分页也保留断点；单批最多 240 次深度 inventory RPC、每根每批 80 页、20 秒读取窗口，未放大原请求预算。
- 并发最多 4 路，逐页轮转；跨批保留调度位置，极小预算也不会永远只读第一个长线程。
- 请求、时间或页数限额产生 `status=paused` 和 `canContinue=true`，不是 RPC 失败。
- 弹窗显示「继续查找（从上次断点）」，以及已完成、已开始、剩余、本批页数、累计页数。
- 真正的网络、权限或格式错误仍保留原始错误；失败页不提交游标，重试从该页开始。
- 断点只存在当前页面内存，使用登录凭证及分支证据的 SHA-256 摘要分区，不保存凭证正文。
- 缓存最多 8 项，空闲 30 分钟过期。关闭弹窗不清空断点；页面刷新、路由切换会清空，凭证或用户分支改变会隔离。
- 追加说明中出现的新 cwd 不会使已读 ID 页失效；弱 cwd 候选每次重新计算。
- 已完成查询的下一次点击重新检查目录；只有新增或元数据已更新的根线程重新下载。
- 查询结束时核对旧节点仍在当前祖先链上，允许正常消息追加，拒绝真实分支替换。

纯文本或 cwd 仍只是待确认候选，不能覆盖显式 ID 冲突。Sonic 调试标识仍不拼成 Codex thread URL。
所有查询只读，不启动/恢复线程，也不发送模型消息。
